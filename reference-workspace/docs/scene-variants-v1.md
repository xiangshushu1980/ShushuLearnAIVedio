# 场景变体的基础参考与空间草稿 v1

Owner: Sean。2026-10-04。

## 使用

在自然语言创作方案中声明场景的基础实体或基础候选，以及明确变化（如长凳磨损、窗户受损、不同时间状态）。新场景变体的首图若没有明确选图，会默认引用基础场景主图；基础主图尚未选定时等待，不能仅凭文字独立重画整个布局。后续角度/细节仍可依赖变体自己的主图。

场景变体默认沿用基础实体已有的空间资料为草稿。在「调整方案」中可关闭「沿用基础场景已有空间草稿」，以便重新设计布局。沿用只复制基础草稿当前版本的方向说明、锚点、关系、路径、未知项：

- 锚点保留原 ID，但引用范围变成新 entityId，便于对照实验。
- 新实体的整体状态为 draft，方向/锚点/连接/路径全部标 pending。
- 不复制基础实体的核对参考图、空间确认或已确认图片组。变体必须用自己的图重新核对。
- 变化说明进入派生资料，并在未知项有空间时附到草稿提示；已有未知项不删除或缩短。
- 基础场景没有空间资料时不生成虚构布局，新实体仍为 missing；之后可交给空间助手建立。

应用后仍是独立实体，已有主图选择、空间助手、场景图片组确认及导出流程继续使用。关闭布局沿用不会取消场景身份的基础图片依赖；若需要全新无关场景，应创建新实体而不声明派生。

## 数据与兼容

创作候选新增可选布尔 `copySpatialDraft`，当前新方案省略时默认：场景变体 true，其他候选 false。true 只允许有基础来源的场景。基础必须为当前项目场景或同方案场景候选。已有明确 referenceAssetIds 的步骤保留原选择，不自动额外加入基础图。

`entity_derivations.options` 保存 copySpatialDraft 和 sourceSpatialVersionId。基础资料后续变化仍通过既有 sourceRevision/派生资料检查处理，不自动覆盖已创建实体的空间版本。

新方案 basis 带 workflowRulesVersion=2。没有该版本的旧不可变方案应用时沿用原来的引用/布局默认行为，不静默加入依赖或布局；重新讨论或保存调整版本后采用当前规则。已经生成的图片、运行、确认和原空间版本不改写。

默认只读导出对 draft 空间仍返回状态和缺失提示，固定事实 elements/links/routes 与 promptContext 为空；includeUnconfirmed 依照原契约提供草稿。未确认布局不会被当作视频提示词中的确认事实。

## 验证

47 项测试及 Vite build 通过。新增 5 项隔离测试覆盖：基础图引用/跨实体复制、已确认基础布局复制成未确认草稿、稳定锚点/来源版本、关闭沿用、同方案基础图等待、明确选图保留、非法来源/选项拒绝、旧规则兼容、未知项达到上限仍完整保留、基础版本不可修改以及默认导出隔离。

PC 隔离色块数据验证了沿用开关、保存新方案、人工应用、独立实体创建和基础主图依赖显示。API 核对新实体保留 entrance/bench 标识、均 pending、无继承核对图、生成运行数0；默认导出 draft 且固定事实/提示词为空。控制台0错误，无横向溢出。证据 experiments/sean_reference_authoring_goal_20261004/scene-variant-{ui-seed.json,inheritance-pc.png,ui-receipt.json}。这些验证不证明真实场景图片一致性。
