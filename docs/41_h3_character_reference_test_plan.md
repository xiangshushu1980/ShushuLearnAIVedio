# H3 人物 Reference 组织方式系统测试计划

> 任务：`remote-c1c2bb3a-432b-4586-af9d-f6ffdde54196`
>
> 目标：回答在 H3 Ref2VA 的 reference 条件有限、且一个镜头包含多个对象时，应该使用独立多图、角色混合板，还是二者的混合方案。
>
> 本文是测试计划；实际生成、盲评和结论在新任务中完成。

## 1. 测试目的

本任务不测试“能不能生成视频”，而测试 reference 组织方式对以下能力的影响：

1. 人物身份：脸、发型、年龄感、体型和整体可辨识度。
2. 服装与身体：服装轮廓、颜色、配饰、身体比例和道具携带关系。
3. 视角补全：正面、3/4、侧面、背面和转身后的同一人物关系。
4. 多对象绑定：两个人物、场景、法术和物品是否绑定到正确对象。
5. 近景细节：脸部特写、说话镜头和手持物是否因 reference 压缩而退化。
6. 条件竞争：增加对象和 reference 后，人物、场景、法术、道具之间是否互相污染。
7. 工程代价：输入数量、显存、耗时、分辨率和 reference 图尺寸对质量/吞吐的影响。
8. 信息冲突与有效像素：同一人物的脸部、服装/体态和视角信息是否因主体占比与重复信息而互相竞争。

最终交付三类结论：单人物默认方案、双人物/多对象默认方案，以及何时必须回退独立多图。

## 2. 待验证假设

### H1：独立多图是身份控制基线

正脸身份图、全身/服装图，以及按镜头选择的侧面或背面图，应该在单人物镜头中提供最强的可解释控制。

风险是 reference 数量增加后，多个条件共同争夺模型容量；H3 公开资料没有给出每张图片的注意力权重或“后图必然衰减”的定量规则，因此这只是待验证的经验假设。

### H2：同一人物的混合角色板可以压缩语义簇

将同一人物的正脸、全身、侧面/背面放进一张干净角色板，可能减少输入对象数量，并使模型把它们理解为同一个角色的整体设计。

风险是每个面板获得的有效像素减少；模型可能复制角色表布局，或无法可靠区分面板中的视角。角色板不能替代近景所需的高分辨率独立脸部图。

### H3：复杂场景适合“按语义簇混合”，不适合“一张总板”

两个人物各自使用角色板，场景使用独立场景图，法术/物品按重要程度使用独立图或效果构图板，可能在控制力和条件竞争之间取得更好平衡。

原则：合并同一个对象的多个视角，不合并不同对象的身份。人物 A/B 不应默认共用一张身份板；人物、场景、法术、物品也不应默认全部合并。

### H4：reference 与 guide 分工可能比继续堆 reference 更有效

场景布局、动作、深度或时间线可以部分作为 guide/anchor，而不是全部作为身份 reference。近期社区工作流已经提供 reference、guide、both 的输入分工，但其对 H3 质量的独立对照尚未建立，本任务将记录该分工是否值得纳入正式路线。

### H5：同一人物应拆分“脸部身份”和“服装体态”职责

同一人物的脸部近景、全身服装图如果都清楚显示正脸，可能会让 H3 在不同尺寸和视角的脸部证据之间产生竞争。候选方案是：

- `face_identity`：高占比脸部图，负责五官、发型前侧和身份；
- `wardrobe_body`：全身/半身图，脸部裁掉或弱化，但保留后脑、发型后侧、颈肩连接、体态、服装、鞋和配饰；
- `view_3q` / `view_side`：只在转身、侧身或三分之四视角镜头中加入，负责该视角的脸部轮廓和发型侧面。

这是待验证假设，不把“去头”直接写成默认制作规则。测试必须检查裁切是否造成颈部、肩线、发型连接和人物比例异常。

### H6：视角补充应按镜头动作触发，而不是按 3 视图/6 视图计数

不比较“3 张一定优于 6 张”。比较的是：

- 没有转身：`face_identity + wardrobe_body` 是否足够；
- 有 3/4 转身：是否需要 `view_3q`；
- 有严格侧身：是否需要 `view_side`；
- 有背身：是否需要 `view_back`。

视图数量只是结果，不是优化目标。

## 3. 对照方案

所有方案使用同一资产、同一 seed、同一 prompt 语义和同一输出设置；只改变 reference 组织方式。

### 3.0 输入槽位与公平性契约

每个样本必须同时记录 `reference_slot -> asset -> semantic role` 映射；图片在槽位中的顺序是实验变量的一部分，不能只记录文件名。默认按下表固定槽位，若工作流无法固定槽位，样本标记为 `invalid_order`，不进入质量统计。

| 槽位 | 允许内容 | 禁止内容 |
|---|---|---|
| `R1` | 主人物身份/角色板 | 第二人物、场景或不相关物品 |
| `R2` | 主人物脸部或服装补充 | 改变人物身份的另一版本 |
| `R3` | 第二人物身份/角色板，或当前镜头唯一的场景/关键物品 | 与 `R1` 重复的裁图 |
| `R4` | 场景、法术或物品（仅在该方案需要时启用） | 未在 prompt 中声明的混合语义 |

方案之间只允许改变资产打包和启用/禁用状态；不得同时改变图片数量、图片内容、prompt 强度、采样器、LoRA、音频、首帧、后处理或裁切策略。R3/R4 的具体语义随方案变化时，必须在记录中写明映射，不能把同一槽位编号误解为同一对象。A 方案也必须按镜头需求裁掉不相关图片，不能把“更多独立图”误当作基线优势。

### A：独立多图基线

```text
Picture 1 = 正脸/3/4 身份图
Picture 2 = 全身或半身服装图
Picture 3 = 按镜头需要的侧面或背面图
Picture 4 = 场景图（按镜头需要）
```

单人物近景不强行加入全身和背面；每个镜头只注入当前需要的图。

A 的正式基线拆成两个子臂：`A-min`（当前镜头所需的最少独立图）和 `A-full`（身份、服装、侧/背视角全部启用）。主结论优先比较 B 与 `A-min`；`A-full` 只回答“堆叠独立图是否反而造成条件竞争”。

### B：角色混合板 + 独立脸部图

```text
Picture 1 = 同一人物的 2–4 面板角色板
Picture 2 = 高分辨率独立正脸/3/4 脸部图
Picture 3 = 场景图（按镜头需要）
```

角色板只包含同一人物：建议一个较大的脸部区域，加全身和一个视角补全区域；不放第二人物、场景、法术、道具文字和水印。B 是本任务最重要的混合方案。

### C：双人物合成板 + 独立脸部图

```text
Picture 1 = 双人物站位/互动构图板
Picture 2 = 人物 A 独立脸部图
Picture 3 = 人物 B 独立脸部图
Picture 4 = 场景或关键物品图
```

只用于验证双人空间关系是否值得用一张构图板压缩。它不是默认生产方案，因为人物 A/B 的脸、服装和身份可能互相污染。

### D：复杂场景按语义簇混合

```text
Picture 1 = 人物 A 角色板
Picture 2 = 人物 A 独立脸部图（近景/说话时保留）
Picture 3 = 人物 B 角色板
Picture 4 = 人物 B 独立脸部图（近景/说话时保留）
Picture 5 = 场景图
Picture 6 = 法术或物品图（二者择一，按镜头主导元素决定）
```

远景可以删除两个独立脸部图；人物近景可以删除不相关的法术/物品图。D 是两个角色、场景、法术、物品同时存在时的首选候选方案。

### E：一张总板（负面对照）

将人物、场景、法术和物品全部排在一张图内，只作负面对照，判断“减少 reference 数量”是否真的抵消了面板分辨率下降和语义边界模糊。

## 4. 资产制作规则

测试资产必须先固定，再开始 A/B；不能边跑边换图。

### 人物资产

每个角色准备：

- `identity_front`：正脸或轻微 3/4 脸，无遮挡，清晰中性表情；
- `wardrobe_full`：全身或半身，服装、体型、鞋和主要配饰可见；
- `view_side`：仅供侧脸/侧身镜头；
- `view_back`：仅供背影/转身镜头；
- `face_closeup`：高分辨率脸部裁图，专供近景和说话镜头；
- `character_board`：由同一角色的 2–4 个视角构成，禁止第二人物、场景、法术、道具文字和水印。
- `wardrobe_body`（T5 候选）：全身/半身服装体态图，减少正脸像素竞争；裁切策略在 T5 中比较“保留后脑/颈肩”与普通全身图，不能预先判定为正确。

角色板建议一个较大的脸部区域，加较小的全身和侧/背视角区域；必须同时保存原始独立图。

### 场景、法术和物品资产

- 场景图不放主角，锁空间布局、光照和色彩；
- 法术图只锁大形态、颜色和几何结构，不承诺逐帧复制；
- 物品图只锁形状、材质、颜色和尺寸关系；
- 法术必须附着在物品上时，可制作一张“法术+物品效果构图板”，但要与独立图比较；
- 所有合成板保留拆分后的独立源图。

## 5. 测试分层

### T0：输入与提示词冒烟

目的：确认图片顺序、标签和职责绑定没有工作流错误。

方法：5 秒、768×448、8 steps、固定 seed、单人物静态中景、标准 Ref2VA 六段式。只检查图片是否互换、角色板布局是否被复制、场景是否污染人物；失败时不得进入质量比较。

### T1：单人物 identity/wardrobe 基线

目的：测量独立多图和“角色板+脸部图”的基本差异。

镜头：正面胸上近景、3/4 半身、全身服装、侧身、背身转回正面、说话近景。

对照：A vs B；每组至少 3 个 seed，至少保留一个 20-step 质量样本。4/8-step 只作筛选，不作最终身份结论。

### T2：多对象低动作

目的：隔离对象绑定问题，不让复杂动作掩盖 reference 差异。

固定场景：两个人物站在同一空间，一件物品在两人之间，一种法术在其中一人手上缓慢出现。镜头为双人中远景、人物 A+法术、人物 B+物品、双人近景对话。

对照：A、C、D；E 为负面对照。记录人物 A/B 是否互换脸、服装、道具和法术颜色。

### T3：复杂场景条件竞争

目的：验证“语义簇混合”是否比所有对象独立输入更稳定。

场景固定包含两个人物、空间布局、一个法术、一个可持有物品，以及至少一次人物与物品/法术交互。

对照：A（所有条件独立）、D（每角色角色板+独立脸部图，场景独立，法术/物品择一）、E（一张总板）、D-guide（场景或动作图改为 guide，人物保留为 reference）。至少两个 seed，并做 8-step/20-step 配对。

### T4：reference 数量消融

目的：测量质量收益是否值得增加输入条件和显存/耗时。

逐项比较：只保留身份图；身份+全身；身份+全身+场景；角色板+脸部+场景；复杂场景 D；删除一个低优先级法术/物品图；将一个图从 reference 改为 guide。

### T5：职责分离、有效像素与视角触发

目的：验证“同一对象多次出现时，重复脸部信息会竞争；服装/体态图应减少脸部信息；转身时再加入 3/4 或侧脸图”的假设。

#### 固定资产

从已经验收的同一角色素材派生，不重新生成新人物，以免把图像生成质量混入变量：

```text
F = face_identity：高占比脸部图
W = wardrobe_full：普通全身/半身，脸部可见
WB = wardrobe_body：脸部去除或裁出画面，保留后脑/发型后侧/颈肩/服装/体态
Q = view_3q：3/4 侧脸或侧身
S = view_side：严格侧面
B = view_back：背面
```

`WB` 不能简单做成无头人体：必须保留自然的后脑、发型连接和颈肩结构；如果裁切后出现明显断颈、假人或比例异常，该资产标记为 `invalid_asset`。

#### 对照 cell

| Cell | 输入 | 目的 |
|---|---|---|
| T5-A | `F + W` | 当前常规人物组合基线 |
| T5-B | `F + WB` | 验证减少第二张图正脸信息后的收益/代价 |
| T5-C | `F + WB + Q` | 验证 3/4 转身是否需要专门视角 |
| T5-D | `F + WB + S` | 验证严格侧身是否需要专门视角 |
| T5-E | `F + WB + B` | 验证背身镜头的专门补充 |
| T5-F | `F + W + Q` | 对照“保留重复正脸再加入侧面”的条件竞争 |

#### 镜头

每个 cell 只跑与其职责相关的镜头：

1. 正面近景/说话：测脸部身份和嘴眼稳定；
2. 中景或全身：测服装、体态、身高比例和配饰；
3. 缓慢转向 3/4、严格侧面或背面：只对相应 cell 启用 Q/S/B。

#### 变量与判定

- 使用同一人物、同一场景、同一 prompt 语义、同一 reference 分辨率和同一 H3 参数；
- 每个 cell 使用至少 3 个 seed，8-step 仅筛选，20-step 才进入结论；
- 记录每张图中脸部/人物主体占画面的比例，作为“有效像素占比”代理变量；不把原始文件像素数直接等同于细节控制力；
- 主要指标：脸部身份、服装体态、视角转换、颈肩/发型断裂、配饰保持、错误脸部混合；
- 若 T5-B 在近景不差于 T5-A、且全身/转身更稳定，才把 `wardrobe_body` 提升为正式角色包组件；否则只保留为特定镜头实验。

T5 不回答“3 视图还是 6 视图更好”，只回答每个视图是否承担了当前镜头所需的独立职责。

### 5.1 重复次数、随机化与停止规则

每个关键 cell 至少使用 3 个预注册 seed；T2/T3 的复杂场景至少使用 5 个 seed。所有方案使用同一组 seed，seed 顺序在跑批前冻结；不得挑选“最好看的一条”代替整组结果。8-step 只用于筛选和失败诊断，身份、近景和对象绑定结论必须由同 seed 的 20-step 配对样本支持。

若某方案在同一 cell 出现 2 次 `invalid_order`、工作流错误或无法解码，先修复基础设施并重跑整组；若出现 2 次以上身份互换、角色板布局复制或关键对象绑定失败，则停止扩大该方案，只保留为失败证据。单个 seed 成功不构成通过。

## 6. 固定条件

第一阶段使用同一普通 Ref2VA 路线，不混入 VDN、MC、FaceRefine、latent upscale 或其他后处理。

默认起始条件：

- 768×448；
- 5 秒、合法 124 帧；
- 8 steps、`res_multistep` 用于筛选；
- 无 LoRA、20 steps、`res_multistep` 用于质量复核；
- 固定 seed、prompt、帧数、采样器、VAE 和音频条件；
- reference 组织测试完成后，才测试 1024×576 或正式长片。

若使用外部音频，所有对照必须使用同一音频和同一 NativeAudioLock 条件。第一阶段也可以使用无对白动作场景，避免声音因素污染视觉判断。

本专题第一轮默认使用无对白、无外部音频的视觉场景；若进入说话近景，才启用同一条音频并将音频条件作为锁定变量。不得把 NativeAudioLock、MC、FaceRefine、latent upscale 或后处理收益归因给 reference 组织方式。

## 7. Prompt 规则

正式对照统一使用 Ref2VA 六段式：

```text
subject_definitions
summary
retention_analysis
detailed_description
overall_soundscape
non_diegetic_music
```

每个 reference 必须有唯一职责：

```text
<Subject 1> is the character defined by <Picture 1> and <Picture 2>.
<Picture 1> is the authoritative identity reference for the face and hair.
<Picture 2> is the supporting reference for the same character's wardrobe and body silhouette.
```

角色板要明确是同一角色的设计资料，不是首帧或场景构图；必须禁止复制角色表布局、标签和文字。

复杂场景必须显式绑定对象：人物 A 的图只定义 A，人物 B 的图只定义 B，场景图只定义环境，法术图只定义法术，物品图只定义物品。不要写“所有图片共同参考整个场景”这样的模糊句式。

## 8. 评价指标

每个视频按 0–4 分记录，并记录失败类型。

### 人物身份

0=换人；1=类别相同但脸明显不同；2=可辨认但五官/发型漂移明显；3=基本稳定；4=近景、运动和跨镜头均稳定。

### 服装与体型

记录服装颜色、轮廓、配饰、鞋、体型和道具携带关系，特别标记服装是否从人物 A 泄漏到 B。

### 视角一致性

记录侧脸、背面、转回正面是否仍是同一人物；分别标记“正脸稳定但背面失控”和“背面正确但转回换脸”。

### 对象绑定

分别记录人物 A/B 是否互换、法术是否附着到正确人物、物品是否复制/丢失/转移、场景布局是否保持、角色板是否被复制成成片画面。

### 近景质量

记录眼睛、嘴、牙齿、头发、手和小配饰；不能用远景“看起来像”替代近景验收。

### 工程指标

记录峰值显存、总耗时、VAE decode 耗时、实际帧数、失败/重跑次数和输出尺寸。

## 9. 盲评与记录格式

输出命名：

```text
<test_id>_<scheme>_<shot>_<seed>_<steps>_<resolution>
```

每个样本保存：输入图片清单及 hash、reference slot 顺序、完整 prompt、seed/steps/采样器/LoRA/分辨率/时长、显存/耗时/错误日志、首中末帧和关键近景截图、评分表、失败标签。

评分先只看匿名视频，不显示方案名称；最后再查看 reference 图进行归因。

盲评表额外记录 `identity_swap`、`wardrobe_leak`、`layout_copy`、`object_transfer`、`face_melt`、`missing_subject`、`invalid_order` 等二值失败标签。统计时同时报告均值、中位数、通过率（身份与绑定均不低于 3 分且无硬失败）及 95% bootstrap 区间；不以单项最高分判定优胜。评审者先按首帧、中帧、末帧和预注册近景截图评分，再看完整视频，避免只凭首帧印象。

## 10. 判定规则

### 默认方案

若混合方案在 T1 中身份和近景不低于独立基线，或在 T3 中人物身份与对象绑定高于独立多图，同时没有明显增加布局复制、脸部丢失和人物互换，则可进入默认候选。

### 特定镜头方案

若角色板在远景/中景改善服装和体型、但近景低于独立脸部图，则规定：远景可用角色板；半身、近景、说话必须搭配独立脸部图或回退独立多图；侧身/背身只加入对应视角图。

### 否决条件

角色板经常被复制成设定表/分镜板；多人物发生身份/服装/声音绑定；法术或物品稳定泄漏到错误人物；近景脸部明显低于独立多图且无法修复；或只有单个幸运 seed 成功而重复 seed 不稳定。

### 统计判定门槛

“默认候选”要求至少满足：关键 cell 的有效样本数达到预注册数量；身份、对象绑定和近景三项的中位数不低于 `A-min` 超过 0.5 分的容差；硬失败率不高于 `A-min` 的 1.25 倍；并且没有 `layout_copy` 或稳定身份互换。若质量相当但显存/耗时明显下降，只能标为“效率候选”，不能写成质量优胜。若不同镜头类型给出相反结果，结论必须按镜头分层，不得压成一个全局默认。

## 11. 任务交付物

1. 固定版测试人物、场景、法术和物品资产包；
2. A–E 方案的 ComfyUI/API workflow 或可复现参数文件；
3. T0–T4 的视频、截图、日志和评分表；
4. 单人物、双人物、复杂多对象的一页结论矩阵；
5. 将稳定当前值更新到 `docs/34_ref2va_generation_guide.md` 或新的专题文档；
6. 将历史覆盖链、失败案例和证据锚追加到 `.pi/ledger/`；
7. 只有经过实际复测的稳定结论，才写入 Mem0，并标记适用条件。

## 12. 当前证据边界

本计划来自官方输入契约、ComfyUI 文档和近期社区原始案例，但社区尚未提供足够的控制变量 A/B，证明某一种角色板布局普遍优于独立多图。

当前社区信号包括：Reddit 角色表作者使用 H3 生成 4/6 面板资料，并建议角色表结合独立脸部/服装近景；X 上近期作者直接使用角色 reference sheet 锁定全片角色，但多为单作者案例；B 站近期工作流集中在故事板、多宫格、四视图和多角色管理，缺少公开严格 A/B；近期 ComfyUI 工作流开始区分 reference、guide、both，并加入 reference analysis/对象映射阶段。

因此本任务的第一目标不是证明某个社区方案“正确”，而是把高概率方案转化为可重复、可盲评、可否证的实验。
