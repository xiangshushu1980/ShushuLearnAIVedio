## 页面关系与入口

本稿不设计创建入口、管理页或浏览页。用户从后续管理/浏览界面选定一个具体实体后进入该实体的创建/编辑会话；本稿只呈现选中实体的创作步骤和面板，不预设上游如何查找或选择实体。

会话内左侧按依赖呈现五个创作面板：设定收集、概念图、主形象、三视图、声音。概念图与主形象属于“主形象确认”这段视觉流程，但在此拆为两个清晰步骤，避免用户误以为是一次生成。三视图等待已确认主形象；声音可以独立开始。步骤状态同时表达锁定原因、生成进度和确认情况。

## 五面板契约

| 面板 | 页面内容 | 关键边界 |
|---|---|---|
| 设定收集 | 实体介绍、已收集设定资料、派生/编辑的提示词版本、保存状态 | “添加资料”只在此出现；保存资料不触发生图 |
| 概念图 | 一张必选主参考、一张可选第二参考、提示词、风格设置、多个候选 | 只把明确选中的最多两张图送入 Krea2 Edit；生成后候选等待审核 |
| 主形象 | 唯一参考输入为已确认概念图；主形象提示词与风格、候选预览 | 不额外选早期设定图；概念图确认后可启动，更换概念图会令旧主形象显示“待更新” |
| 三视图 | 已确认主形象、固定三视图生成、合成图预览 | 前置主形象未确认时不可启动；一个合成图作为单个结果确认 |
| 声音 | 提示词或音源与准确转写、系统提供的试听台词、多段候选试听 | 与视觉流程并行；BGM 不在本阶段 |

右侧各面板统一采用“输入与参数 → 运行状态/进度 → 输出预览 → 确认/恢复 → 可选 ComfyUI 详情”的顺序。只要新运行尚未确认，原确认版本仍是当前版本。ComfyUI 入口从当前 run 打开；只有能定位同次运行时才显示为运行详情。日常生成、进度查看和结果审核留在 Reference 工作台完成。

### 概念图面板：具体使用方式

概念图用于根据当前选定的参考图和目标提示词生成一张目标形象图，以便确认整体气质、风格和情境。以林岚为例，用户先在设定收集面板登记人物介绍和多张设定图；进入概念图后，从已收集资料中选择一张必选主参考，并可再选一张第二参考。界面只把这两项显式选择的图片送入本次 Krea2 Edit 运行，其余已关联资料不会自动混入。

提示词从详细介绍（尤其外观）派生，用户可补充这次希望呈现的情境并保存新提示词版本。用户运行固定模板后，在面板查看进度和候选；候选不覆盖当前确认图，用户明确确认后才成为新概念图。再次生成时保留本次实际使用的图片及版本、提示词版本和模板版本，便于之后判断哪些下游结果需要更新。

主参考/第二参考只是输入槽位，不预设它们分别代表“身份图”“风格图”等语义角色。JIBS 与双图输入的组合仍待烟测验证；设计稿展示风格选项不代表该组合已通过验证。

### 实体介绍与提示词的 Agent 边界

实体介绍和各步骤提示词可以由 Agent 协助建立并写入实体资料；用户始终可以手动编辑。介绍文本与步骤提示词分别保存、分别留版本，手工修改的提示词不能被 Agent 输出或介绍更新静默覆盖。介绍变化时，只将依赖它的提示词标记为待复核；用户显式调用 Agent 生成新稿，再比较并决定是否采用。当前 UI 设计只明确可编辑文本、来源版本和保存状态；是否提供应用内 Agent 按钮、使用何种 Agent/API 或接入 Pi/Codex，留到后续实现方案确认，本轮不嵌入 Pi/Codex 会话或 CLI。

### 风格配置

概念图以选择已保存的风格配置为主路径。主形象默认沿用当前概念图风格配置，同时可以切换到另一已保存配置并启动新运行进行尝试；新候选沿用既有确认/恢复规则。当前界面不展开单项 LoRA 权重、风格参考图或风格提示词等底层参数。

## 评审重点

1. 用户从后续管理/浏览界面选中实体进入创建/编辑时，当前实体是否足够明确。
2. 用户是否能理解概念图、主形象是两个先后审核的生成步骤，三视图依赖主形象，声音可并行。
3. 五个面板统一位置后，生成中、待审核、已确认和恢复操作是否足够清楚。
4. “可选 ComfyUI 运行详情”措辞只用于已验证能定位同次运行的入口；否则先隐藏该按钮或改成准确的能力描述。
5. 产品名、实体类型标记与状态颜色仍可在产品评审中调整；本稿不冻结命名或完整实体分类。
