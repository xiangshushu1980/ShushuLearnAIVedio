# H3 二采与远景脸防糊方案：分流策略与深度探索

> 任务：T-comfy-ops-46  
> 日期：2026-09-20  
> 范围：基于 T-comfy-ops-43/44/45 的本地 RTX 4090 实测，整理远景小脸的可生产方案；本轮不重复启动共享 ComfyUI。

## 结论先行

当前没有一条“二采后必然恢复远景身份细节”的 H3 单步方案。远景脸的主瓶颈是源视频中的脸部像素和姿态信息，不是最终输出尺寸。应按源脸高度分流：

| 源脸高度（粗略） | 首选路径 | 目的 | 生产判断 |
|---|---|---|---|
| `<30 px` 或正面信息不足 | 生成阶段改构图、短暂 push-in/中景锚定，或接受脸不可读 | 增加源信息 | 后期二采不应承诺恢复身份 |
| `30–60 px` | 坐标锚定 + 平滑跟踪的 768 局部 H3 refine；必要时按人串行 | 防跳脸、稳定轮廓和贴回 | 已验证可用，细节增益通常很小 |
| `60–120 px` | 768 局部动态 denoise refine；单人/多人分开处理 | 在可读阶段增益细节 | 当前最有价值的局部修复区间 |
| 全画面需放大且重视运动连续性 | 一采 latent → learned 3D latent upscale → H3 refine | 减少 VAE 往返，保持全片结构 | 已通过 5 秒；远景细节收益未证实 |

## 已验证事实

### 1. 局部 H3 FaceRefine 的边界

T-43/44 已验证 `H3FaceTrackCrop → H3InjectVideoLatent → H3PerFrameDenoise → H3FaceStitch(face_only)` 在 4090 上可运行。768 方形 crop、base denoise 0.40、8 steps、动态 denoise 在单人动态侧脸和稳定双人场景中能够保持跟踪、动作和贴回稳定；多人必须按人串行处理。

在严格远景样本中，源脸约 30–50 px。坐标锚点 `closest_to_xy` 加时间平滑能解决小脸/兜帽角色被错误选择的问题，但极小脸的身份细节增益几乎不可见。中景到远景的 pull-back 对照也显示：中景阶段有轻微改善，降到约 40–60 px 后收益快速消失。

结论：局部 refine 对远景的主要价值是 temporal/identity safety（不跳脸、不抖、不错误补一张正脸），不是凭空创造身份细节。

### 2. 完整视频 latent 二采的边界

T-45 已安装 `MinimaxH3LatentUpscaler3DRefineHandoff` 与 BF16 权重，并完成 49 帧 smoke 和 124 帧正式测试。正式配置为：一采 768×448、124 帧、H3 8 steps；latent upscaler 目标请求 1344×768、refine 4 steps、denoise 0.40、BF16、音频锁定。实际输出为 1376×800、124 帧、约 5.17 秒，约 125 秒完成，无 OOM，峰值约 22.9/24.6 GiB。

视觉初判：构图、人物位置和远景状态保持稳定，未见明显跳脸、强制近景化或错误重画；但远景脸仍模糊，细节增益有限。这支持“latent 二采适合全片结构/时序保持”，不支持“latent 二采已经解决远景脸”。

注意：请求 1344×768 实际得到 1376×800，源片 5.17 秒；不能把该片当成严格 1344×768 或与不同帧数样本做逐帧质量结论。

## 推荐生产管线

### A. 先在生成阶段争取像素

如果脸是叙事信息，优先让镜头在前段保留 60 px 以上的头部，使用单镜头 push-in/pull-back 或中景锚点，再进入远景。提示词应明确连续运镜、人物屏幕位置、动作和远景目标，但不应把“sharp face”当成信息恢复指令。H3 prompt 继续遵守 Ref2VA 六段式；此问题是工作流与构图问题，不靠负面提示词解决。

### B. 对可读脸做局部 refine

推荐链：

```text
源视频
  → H3FaceTrackCrop（单人；多人按人串行）
  → 768×768 crop，crop_factor≈3
  → H3InjectVideoLatent
  → H3PerFrameDenoise（脸高驱动）
  → 8-step H3 refine
  → face_only stitch，保留原音频
```

当前安全基线：base denoise 0.40、8 steps、small-face multiplier 1.0、large-face multiplier 0.35、脸高 30–120 px 插值、smooth_frames 9；坐标不可靠时用 `closest_to_xy`，不要依赖“最大脸”选择兜帽/小脸目标。快速转头、硬切、严重遮挡和多人交叉遮挡需要按镜头切段或人工 ROI。

### C. 对全片做结构性二采

当目标是整体尺寸、背景和动作连续性，而非局部脸细节，使用完整 latent 二采。它避免 `latent → VAE → pixel upscale → VAE → latent` 往返，适合低分辨率一采到高分辨率交付。二采后若再做脸局部 refine，应先检查显存和目标脸像素，不要默认两次重画都会叠加收益。

## 建议的下一轮严格对照

若要把当前“视觉初判”升级为可复核定论，必须使用同一源片、同一帧数、同一输出网格，并保留音频之外的纯视频对照：

1. A：原始一采低分辨率；
2. B：完整 latent 二采；
3. C：局部 768 refine + stitch；
4. D：完整 latent 二采后局部 refine（只在显存允许时）。

每条都抽取同一时间点和同一人物 ROI，记录：脸部有效像素高度、身份/轮廓可读性、帧间漂移、闪烁、错误补脸、背景变化、动作保留、显存峰值和实际输出网格。评价应分为“稳定性”和“细节恢复”两列；不能用放大后的锐度或单帧观感代替身份稳定性。

## 尚未验证与风险

- 尚未完成严格同源、同帧数的 B/C/D 逐帧局部指标对照。
- 尚未验证 D 是否比 C 更好；latent 二采可能先改变源脸，再增加局部 refine 的输入不确定性。
- 尚未验证专用 1× 细节模型/VOSR2 在当前本地环境的真实收益；不能把社区或云端效果当成本机结论。
- 1344 请求到 1376×800 的对齐行为必须在生产脚本中显式裁剪或调整目标网格。
- 外部对白/音频应在后期或 NativeAudioLock 链路中作为真值；不要在仅为画质测试的 prompt 中虚构对白。

## 操作底线

- 共享 ComfyUI 视为单实例；H3 任务串行，先检查队列与共享资源。
- 768 refine 已接近 23 GiB 峰值；4090 上不并发多人处理。
- 所有结果按“source / smoke / production / simplified”标记；4-step 探测片不能作为画质基线。
- 远景目标若只有 30–50 px，应把验收重点放在不跳脸、不抖动、不错误补正，而不是要求恢复不可见的眼鼻口细节。
