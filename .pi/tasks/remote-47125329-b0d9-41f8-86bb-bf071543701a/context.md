# ComfyUI H3 视频生成工具讨论上下文

> Owner: Sean

## 目标

本任务用于讨论和规划一个基于 ComfyUI 的 H3 视频生成工具。工具希望把 H3 视频从素材/reference 准备到生成、review 和重新生成的流程组织在一起；当前阶段先明确需求与可执行路线，不预设具体技术架构。

## 第一阶段：创建 H3 所需的 reference

首要工作是设计并建立 H3 生成所需 reference 的创建流程。用户希望以可视化方式创建和配置所需设定，并将相关工作流整合起来，包括：

- 可视化地创建、整理 reference 所需的设定。
- 多视图/多视角 reference，以及多视角 LoRA 相关工作流。
- H3 视频生成流程。
- 描述/提示词相关工作流。
- 声音/音频相关工作流。
- 变体生成与管理工作流。
- 对生成结果进行 review，并可根据 review 调整后重新生成。

## 本轮已确认的创建/编辑决策（2026-09-30）

- 当前聚焦 Reference 实体的创建和编辑；Media Browser 是创作参数、步骤依赖和结果审核的入口。ComfyUI 工作流/节点是固定生成模块，运行期不修改；用户可在 Media Browser 设定提示词、素材、选项及路径规则。
- 启动后进入 ComfyUI 查看节点、中间预览、固定分支与执行状态；完成后返回 Media Browser 汇总、审核和登记最终素材。不要在 Media Browser 重做节点预览。
- 解耦实体数据、创作会话、工作流模板/输入契约、参数映射、ComfyUI 执行适配器和素材登记。
- 流程是依赖图而非单线：概念设定和角色形象确认后才能生成三视图；提示词确认后声音可独立并行启动。
- 暂不做分支管理，也不冻结完整关系类型和关系管理界面；但数据设计必须支持实体关系后补、改链和修订，并追踪其对生成结果的影响。当前任务已增加 `docs/48_h3_reference_creation_editing_flow.md`，并在 `docs/INDEX.md` 登记。
- 当前没有新 UI/桥接实现可执行集成烟测；实现后需验证参数映射、模板不可变、ComfyUI 预览与会话关联、声音并行/视觉门控和结果回流。工作流内部是否有分支选项、会话草稿留存时长、具体运行关联机制都尚未冻结。

下一步：依据创建/编辑功能与使用流程设计 UI 故事板并评审；之后再讨论查看和管理是否共用页面，以及实体关系模型。

## 查看与管理首版范围（2026-09-30）

- Media Browser 首版查看管理以搜索、浏览、预览为基础；轻量管理增加删除。
- 所有删除统一进入回收站；支持还原或彻底清空。此规则适用于后续加入的删除功能。
- 使用 flag 为实体筛选；所有实体可加 flag，常用 flag 自动排前。默认 flag：人物、物品、技能、场景。
- 当前暂不细化完整实体关系界面；此前建议为同一 Media Browser 内独立查看工作区和创建/编辑工作区。
- 待确认：已有实体的 flag 是否可在查看工作区修改（否则在创建/编辑流程中赋值）；多 flag 筛选的组合逻辑与常用度统计范围；删除实体时其素材的回收/还原粒度。

## 创建/编辑界面补充（2026-09-30）

- 用户认可创建/编辑界面方向，并进一步确认：左侧列出“设定收集”“主形象确认”“三视图”“声音”；点击选项后右侧展示详细设定、结果、重生成操作与生成进度。主面板布局固定。当前右侧草图只展示概念图详情。
- 输入图片和提示词可持续调整。重新生成不覆盖已确认结果；生成后由用户选择保留新候选或恢复此前确认版本。复杂分支树暂不做，但必须保留当前确认版本以支持回退。
- 默认留在 Media Browser 直接生成、观察状态/进度、等待并查看结果。ComfyUI 是可选入口，用于查看同一次生成的流程节点和中间结果；打开不改变外部生成及结果回流。
- 删除实体时其关联素材可能被多个实体引用；实体进入回收站及可恢复期间，素材引用保持不变；从回收站彻底清空实体时才减少相应引用。引用归零后暂不自动清理素材。
- 创建/编辑流程复核：设定收集保存早期参考图片；概念图和主形象都以设定图片、提示词和风格通过 Krea2 生成，概念图确认后生成/确认主形象。Midjourney JIBS 是用户已有的图片风格 LoRA，风格可以由提示词、输入图和 LoRA 共同决定，后续集成可复用风格设定。三视图使用既有 Krea2 + 多视角 LoRA 流程（不含自行训练 LoRA）。声音支持仅提示词或外部音源输入并按提供内容选择 Breeze TTS 模式；音源模式需要准确转写。系统按题材与情绪模板预置台词生成样音供用户试听，不要求手工录入试听台词。用户可在 Media Browser 直接生成、看进度并审核；ComfyUI 是可选的同次运行细节查看入口。输入可修改和重跑，候选不覆盖确认版，用户选择保留候选或恢复旧确认版。
- 创建/编辑工作台 UI 草图 v1/v2/v3：`docs/design/sean_h3_reference_creation_workspace_v1.png`、`docs/design/sean_h3_reference_creation_workspace_v2.png`、`docs/design/sean_h3_reference_creation_workspace_v3.png`。v3 按最新收敛范围更新，并由 `docs/48_h3_reference_creation_editing_flow.md` 引用。

## 实体关系与生成结果的持续修订（2026-09-30）

- 用户补充：物品/实体收集时，关联对象可能还没有建立；后续需要能持续补建关系。已建立关系中的被引用对象（如人物手中的武器）也可能再修订，修订后可影响概念图、主形象等生成结果，且这些结果都可能重新生成。
- 产品约束：不要求所有关联实体同时建好；可以暂存待关联项，等目标实体创建后解析成正式关系。生成运行要保存当时实际采用的实体、关系、素材版本、提示词和参数快照。
- 被引用实体/关系/素材变化后，只标记实际依赖变更输入的结果“需复核/可重生成”，不自动覆盖确认结果或触发生成。由用户查看影响、调整输入并显式重跑；旧运行与确认结果保留可追溯。未使用该对象的结果（例如声音未引用武器）不应受影响。
- 完整关系类型系统及录入 UI 尚待讨论；当前以兼容这种后补关系和版本依赖为设计底线。`docs/48_h3_reference_creation_editing_flow.md` 已更新至 v1.0。
- 用户确认：关联物品更新后应持续标记“已更新”，依赖它的形象持续标记“待更新”；只有使用新 ref 生成并确认新版形象后才清除待更新状态。生成但未确认的候选不能清除此状态。流程文档更新至 v1.1。

## 图片与文字流程逻辑审查（2026-09-30）

- 用户确认：概念图是利用提示词和参考图片生成目标图片；提示词可表达情境/相关设定。主形象以已确认概念图为参考图生成，作为主要视觉基准。
- 用户确认：目标介绍会很详细，可能从小说总结；图片提示词从介绍中生成，尤其是外观。介绍与派生提示词应分别保存版本；提示词编辑不能覆盖介绍。
- 用户确认：武器、服装、发型等是角色的多种设定；重要武器/物品独立建实体，可被不同角色复用，关系是多对多，生成运行记录实际选择的对象和版本。
- 审查约束：运行状态和资料新鲜度分开显示；依赖更新沿实际生成链传播（物品/关系→概念图→主形象→三视图），逐级依据新 ref 生成并确认后清除相应待更新状态。
- 依赖失效需沿实际生成链传播：旧武器/关系影响概念图，主形象依赖旧概念图时也待更新，三视图依赖旧主形象时继续待更新。每次运行记录素材 ID 和版本。逐级用新输入生成并确认后才清除相应待更新状态。
- 技术证据差异：当前 Krea2 设定图+提示词+JIBS 的组合目标还需对照 `docs/40_krea2_prompt_and_identity_pipeline.md` 的分阶段身份/移除/JIBS管线；Krea2+QuadView 合成三视图虽有探索实测，但仍非 canonical 且未通过 H3 消费验证（见 `docs/45_ref_asset_handbook.md` 和实验 manifest）。
- 能力核查：Krea 官方产品的生图入口支持 prompt+reference image，并列出 Krea 2；官方开源 Krea2 推理仓库展示的是 text-to-image 接口。本地 ComfyUI 可通过社区 Krea2Edit 扩展及 Identity Edit LoRA 使用一张主参考图和一张可选第二参考图，不属于 vanilla Krea2 文生图节点原生输入；没有证据显示可像 H3 Ref2VA 那样接任意多张 ref。
- 第一阶段图片输入收敛：概念图为主参考图+可选第二图+提示词；超过两张的关联物品 ref 暂不接入，显示“已更新”即可。物品关系和版本数据仍保留。主形象以已确认概念图为参考图生成。
- 用户确认先粘贴/注入详细实体介绍；后续才做小说导入系统。图片生成提示词从详细介绍（尤其外观）派生，介绍和提示词分开版本化。
- 下一任务待处理：Krea2Edit 双图+JIBS 组合烟测/工作流输入契约；小说文本与图片提示词审阅/修改交互；多套设定组合及后续 H3 Ref2VA 多 ref 映射；三视图合成图 H3 下游消费验证。流程文档更新至 v1.6。

## 待确认的细节（2026-09-30）

- Krea2 风格 UI 如何协调提示词、设定图和 Midjourney JIBS 风格 LoRA，并沉淀为后续可复用的风格设定；是否给用户展示一个简单风格设置并隐藏底层组合细节。
- 概念图确认后，主形象生成是否以已确认概念图为直接参考输入（前期设定图是否也继续作为输入）。
- 用户确认的 Krea2 + LoRA 三视图测试流程具体布局为左脸近景/中全身正面/右全身背面；确认产品三视图沿用这套布局。
- 外部音源/纯提示词两种 Breeze TTS 模式分别如何选择及哪些设置共用；准确转写在音源模式提供。外部音源生成/处理的结果和模板试听样音是否可选定并登记为正式声源。
