# 参数经验（4090 实测 + 官方/社区参考）

> 本册收集所有参数结论。主 SKILL.md 只保留最常用的。
> **来源标注**：`[官方]`=模型作者/官方模板（含出处与理由）；`[社区]`=社区来源（含来源+适用配置，非 4090 或不同栈慎用）；无标签=本地 4090 实测（含日期）。官方/社区值只作参考基线，偏离前先想理由。

## 速度表（Wan2.2 Lightning）
- 480²×17帧 ≈ 9-16s ｜ 384²×17帧 ≈ 7s ｜ 33帧 ≈ 14s ｜ 49帧 ≈ 17-21s ｜ 41帧@8fps(5秒视频) ≈ 12-16s
- **帧数-耗时实测斜率（2025-08-01，480²×6步）**：33→49 帧 ≈ 0.54s/帧 → 41帧 ≈ 24s / 81帧 ≈ 45s（近线性，固定开销被摊薄后几乎线性）
- **5 秒视频标准配置（2025-08-01 定）**：**41帧 @ 8fps**（生成 ~24s，比 81帧@16fps 快一半；81帧 更流畅但 45s）——默认用 41帧@8fps，除非对比需要
- **生成时间由帧数决定，不由秒数决定**：30fps×2s = 10fps×6s = 同为 60 帧 = 同样耗时；fps 只影响播放速度
- **模型切换成本 ~45s**：生图(anima-base/krea2) ↔ 视频(Wan GGUF) 互切时，GGUF 需重新加载（Hi 5GB + Lo 8.5GB×2）→ 总耗时变 50-80s；连续同类任务则只有 10-16s
- 步数 4→6 几乎不增耗时（6 步是免费质量提升）
- agent 测试推荐：480²×17帧×4步 cfg 1.0 ≈ 10s/次

## cfg（画面修订度，2025-07 实测对比 1.0/1.2/1.5/2.0/3.0/4.0）
- **1.0 最自然** ｜ **1.2-1.5 甜点区** ｜ 2.0 开始画面改动大 ｜ 3.0+ 过曝/饱和

## 时序能力（4 步蒸馏 vs 标准模式）
- **4 步蒸馏 ≈ 单动作**（多动作序列丢失，只保留最后一个；双动作转身+挥手实测只剩挥手）
- **标准模式(20步/cfg3.5/shift8) 实测（2025-07-31）**：动作幅度更大（帧差峰值 14-15 vs Lightning 11.8），但 33/49 帧均只有开头一个动作阶段（转身在 1 秒内完成，之后完全静止）→ 多动作序列同样失败，只是幅度差异。Hi/Lo 分流 0-10/10-20 已测
- **动作分布规律**：Lightning=持续小动作（cfg1 画面自由）；标准=开头大动作后静止（cfg3.5 画面锁死）
- 若需多动作：试标准模式降 cfg、81帧+（未测）、或 Pusa/artokun-flow 等管线（MCP 有现成包，未测）

## 分辨率/帧数约束
- Wan 约束：分辨率 16 倍数，帧数 4n+1
- **起始图分辨率实测（2025-07-31 确认）**：WanImageToVideo 把任意起始图双线性缩放到目标 480²（源码 nodes_wan.py common_upscale bilinear/center）。
- **底图分辨率 vs 视频质量（2025-08-01 严格实验，同 seed/同提示词/骑士图 5 档）**：**底图分辨率 → 视频清晰度线性正相关**（512→1792²，视频清晰度 539→979，+82%）；**底图自身锐度分与视频清晰度无关**（512 底图锐度 665 反而最高但视频最糊）——高分辨率底图缩放保留更多细节。**修订旧结论：768² 不是最优，用原图（1024-1792²）直接跑增益持续**；768² 仅剩构图可控/加载优势
- **底图分辨率不影响动作内容**（5 档动作幅度 18.1-19.0 持平，±5% 内；旧“512 底图动作更大”未复现，可能为噪声/内容差异）
- **分辨率不影响耗时**（512-1792² 均 21-30s，差异仅来自首任务模型加载）
- **多底图×多帧数实测（2025-08-01，6 步）**：帧数基本不影响清晰度（17/33/49 三档每底图清晰度接近）；**动作幅度随帧数增长**（时长给动作发展空间）→ 帧数=时长，清晰度=内容+分辨率
- **底图内容决定清晰度基线**：机甲 3938 >> 森林 2765 > 甜点 2170 > 夜景 1421 > 人物 1029 > 太空猫 179（细节丰富度强相关）
- fps 只影响播放速度不改变内容；分辨率只影响清晰度不改变语义
- 5 秒视频 = 41帧@8fps 或 81帧@16fps（41 帧生成更快）

## Bernini v2v 编辑参数（2025-08-02 实测，int8 + Turbo 6步）

| 配置 | 帧数/分辨率 | 耗时 | 清晰度 | 备注 |
|------|------------|------|--------|------|
| int8 cfg1.0@8fps | 41帧 480² | ~70s | 1015 | 旧基线（5s）|
| int8 cfg1.0@16fps | 81帧 480² | 110s | 1320 | 5s，清晰度最高 |
| int8 cfg1.5@16fps | 81帧 480² | 120s | 1128 | 5s，cfg 高反而压低清晰度 |
| **int8 cfg1.0@16fps 10s** | **161帧 832×480** | **1310s** | 870 | ⚠️ 非线性爆炸，22 分钟 |
| int8 cfg1.0@16fps 10s | 161帧 640×360 | 待测 | — | 降分辨率省时候选 |

- **cfg 结论**：编辑任务 cfg1.0 最稳（让模型信任源视频细节）；cfg1.5 压低清晰度且动作步伐易乱
- **fps 结论**：@16fps 动作比 @8fps 连贯（帧间差异 22 vs 16），官方默认 16fps
- **⚠️ 时长匹配铁律（2025-08-02 关键）**：**Bernini 源视频时长必须 == 输出时长**！10s 源压进 5s 输出 → 后半段脑补/步伐混乱；10s→10s 匹配后自然连贯（用户目视确认）
- **非线性成本**：161帧@832×480 耗时 1310s ≈ 81帧@480² 的 12 倍（帧数×2 + 面积×1.73 ≈ 理论 3.5×，实际 12×）→ 长序列 attention 成本非线性 + 显存压力回退
- **耗时预算**：5s 编辑 ≈ 110s（int8）/ 10s 编辑 ≈ 22 分钟（除非降分辨率）

## Bernini 模型加载/显存（2025-08-02 实测）
- ComfyUI 默认 NORMAL_VRAM：任务间模型**不释放**（缓存最近使用的），空闲时显存仍占 ~11.8GB（Bernini int8 高噪驻留）
- 同模型连续任务命中缓存快；Wan2.2↔Bernini 互切才重载（+45s）
- **WSL 内存配置**：默认 32GB（宿主 64GB 的 50%）→ 2025-08-02 改 `.wslconfig` 加 `memory=48GB`（需 wsl --shutdown 重启生效）
- ⚠️ OOM 教训：Bernini 任务 python 进程可到 ~30GB，32GB 上限必炸（两次崩溃）→ 48GB 后安全；仍避免同时跑多个大任务

## 参考图准备规范（通用，跨模型，2026-08 调研）
> 来源：Magic Hour CEO 指南 / LTX 官方教程 / MindStudio / r-StableDiffusion 高赞 / 本地实测；详细论证在 Mem0（comfy-ops 池）
- **机制分两类**：单图输入（Wan2.2 I2V / LTX）= 参考图即首帧，构图即画面，**九宫格拼一张必失败**（模型把格子当场景），角色表必须裁成独立图，构图要匹配目标首帧；多图输入（H3 Ref2VA / Kling 多图）= 每图独立 slot + 标签定位，九宫格拆开喂
- **数量甜点 2-4 张**（正脸特写 + 全身正面 + 可选背面/佩饰）；9 是上限不是目标；同维度冲突细节（光照/表情/角度不一致）→ 特征平均 → 身份漂移；不同维度互补（人物+场景/风格）才有增益
- **细节物理上限**：VAE 8x 下采样 + 输出 480-576p，微细节编码阶段就丢 → 参考图只锁大特征（脸型/发型/服装轮廓/配色/标志道具），细节靠 prompt 文字 + 后期超分
- 跨片段：同一张参考图锚定身份；帧链（上段好帧当下段参考图）

### 加速策略（2026-08-15 定稿，start.sh 已去全局 sage 改节点级）
- **默认 = Sage 节点**（`PathchSageAttentionKJ` sage_attention=auto，KJNodes 实验节点，插在 LoraLoader 后）：实测 @1024×576 8步 124帧 wave 44.3s / dance 43.9s ≈ 纯 attention（91.8s/66.8s）的 **1.5-2x**；与旧全局 sage（45s）一致，行为等价
- **Sol-Attn 弃用**：耗时与 Sage 持平（44.9s/44.6s，无速度优势）但高动态 dance 鬼畜崩、且首轮 1.07x 对比失真（当时 baseline 实为全局 sage）→ 无存在价值，不再使用
- **高动态内容**：Sage 有穿帮但明显轻于 Sol（可接受）；极端高动态可选纯 attention 兜底（不插节点即可，代价 1.5-2x 耗时）
- **马赛克澄清**：首轮"sage 浪头马赛克"未复现（wave 三方式均无马赛克，疑 seed/内容相关），不构成 sage 系统性问题
- 对比产物：ComfyUI/output/video/attn3way/ + output/compare/attn3way_{wave,dance}.png（行=50%/75%帧，列=plain|sage|sol）

- **模型选择**（官方 README 2026-08-10 查证）：DiT 官方首选 int8_convrot（需 torch cu130，本地 2.13.0+cu130 ✓），fp8_scaled 仅兜底；TE 用 nvfp4_awq（15.7G，官方确认无需 Blackwell，4090 可用 ✓）

### 提示词控制技巧（2026-08 A 测试 + 官方指南，详见 docs/10 案例库）
- **渲染风格词主导（2026-08-12 实测，T-20260812-07）**：i2v 快车道下 prompt 风格词决定渲染风格，首帧只锚定身份/构图——`Live-action, cinematic` → 真人写实（同首帧 aliya_1024）；`Anime style, cinematic` → **真实光照/真人质感 + 卡通渲染动漫角色**（V7 混合风，用户点赞需记录；配置=int8_convrot+v4-600EMA 8步@1024×576）
  - 生产规则：要写实 → Live-action；要动漫 → Anime style（产出带真实光照的卡通渲染）；纯 2D 动漫 → 动漫首帧 + 不写人物描述（337 字版已验证风格完全跟随首帧）
- **镜头语言是最强控制**：类型+幅度+速度（如 `pans right with large amplitude at fast speed`）→ 动作量 3-3.5x（实测 J2/J3）；官方四要素表：Zoom/Push/Pan/Truck/Tilt/Arc/Tracking/Static/Shake/POV/Roll × small/large amplitude × slow/fast speed
- **动作形容词梯度生效**：`gently` → `strongly and energetically` 1.7x（J4/J5）；动作序列用逗号/连词串（走→停→挥手→转身）
- **约束指令**：`strictly preserving her face and clothing` 有效（主体锚定）；**勿与运动指令同句**（矛盾时模型优先运动，J7 场景保持无效案例）
- **结构**：I2VA 用官方指令头 `For the target video, at 0.00 seconds, <Picture 1> (from [Shot 1]) is fully referenced.` + 三段核心字段（integrated_multimodal_description / overall_soundscape / non_diegetic_music）；ref 模式六段式（subject_definitions / summary / retention_analysis / detailed_description / overall_soundscape / non_diegetic_music）
- **声音指令**：环境声（风/雨/海浪/鞭炮/古琴）强；鸟鸣等细粒度弱需 `loud and clear` 强调（C22）；对话用 `<d>[语言] ...</d>`
- **全英文 prompt**（p7 中文验证无效）；**详细度与速度无关**（六段式 159s = 普通 prompt）→ 写详细不付时间成本

### 关键参数
- **steps**：14 步快速看效果（眼睛细节略崩）/ 20 步成片（声音明显更好）；画面 16-20 接近
- **scheduler/sampler**：simple + res_multistep（官方默认）；**无 cfg**（BasicGuider，CFG-distilled）
- **分辨率**：1024×576 画质均衡甜点；768×448 快 30-40%；1344×768 10s+ 成本非线性飙升禁用
- **时长**：5-15s（trained 124-362 帧）；15s 动作较简单；首尾帧双 keyframe +52s
- **SageAttention 默认开**（节点级 PathchSageAttentionKJ auto，2026-08-15 起）：10s 快 40%、15s 快 48%（长序列收益大）；768 系列影响小；Sol-Attn 已弃用（无速度优势+高动态崩）
- **MotionCache**：**14 步下无实用价值**（默认只跳 1/14；激进参数 warmup2/thr0.25/maxskip3 跳 4/14 但 score 开销抵消，净收益 ~3s）；**仅 20 步画质档可作加速选项**（1.25-1.33x）；**音频劣化主因是 MC 跳步**（sage 对音频零影响：0.2 LU 不可辨）
- **量化**：fp8_scaled（4090/Ada 原生 fp8，画质更好同速）；30系用 int8；GGUF 暂不可行（加载器不支持）
- **显存**：fp8 驻留 17.1GB / int8 13.9GB + offload；文本编码器 nvfp4_awq 15.7GB 全量入显存
- **铁律**：跑批前重启 ComfyUI（内存压力下慢 2 倍）；start.sh 勿加 --enable-asset-hashing（视频多了 RSS 33GB）

### Ref2VA 参考
- 单图参考零速度惩罚（~150s 5s）；多图（≤9）可用 `<Picture N>` / `<Subject N>` 标签
- **甜点配置**：正脸特写 + 全身正面 +（可选）背面/佩饰 3-4 张，同光照同服装；佩饰仅当剧情关键道具才给，接受被简化
- **角色分配**：每图在 prompt 显式定义角色——`<Subject N>` 身份/道具、`<Picture N>` 关键帧/构图锚点，retention_analysis 写保留关系（官方 ref 指南 /tmp/guide_ref.md）
- 场景/风格用独立图与人物分开喂（本地 C06-C19 共 8 个多图案例验证融合可用）
- **视频参考必须 CLIPLoader device="cpu"**（否则 24GB 显存打爆卡死；+600s CPU 编码）
- ref_image_size max 仅对 >2048px 图有增益
- 声音指令：风/雨等环境声生效；鸟鸣等细粒度弱；`<d>` 标签可触发对话

### Ref2VA Turbo（2026-08-13 lightx2v v0.1，8-14 起本地可测）
- **规格**：4 步蒸馏（NFE 4）、544p 训练（mixed AR）、shift 12/3、euler + simple scheduler、无 cfg（BasicGuider）、LoraLoaderModelOnly 接入（strength 1.0）
- **与 FL2V Turbo 区别**：条件=参考图/视频/音频（非首末帧），走 MiniMaxH3ReferenceToVideo 节点；参考图接 ref_image_0~N
- **官方工作流**：video_minimax_h3_ref2v_lightx2v_turbo.json（默认 960×544 16:9 0.5MP、5s=124 帧）；Ref2VA 图用 ref2va 基础模型（非 fl2va）
- **官方 ref_image_size 三策略**（ModelTC 仓库）：match=缩到目标像素面积（蒸馏训练一致，推荐）/ max=2048 短边 / diffusers=固定 2048 短边（旧行为）
- **六段式 prompt 结构**（官方示例）：subject_definitions（定义 Subject N 身份）→ summary → retention_analysis（保留关系）→ detailed_description（分镜）→ overall_soundscape → non_diegetic_music
- 本地对比：成片档 F（v4-600EMA 8步@1024=158s）为基线；ref2v 4 步预期速度优势待实测

### FaceRefine 精修参数（2026-08-14 实测定论）
