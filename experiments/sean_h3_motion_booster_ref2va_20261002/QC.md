## 画面与动作

抽帧对照中，角色、服装和法杖维持可识别。两档 LoRA 都出现明显白色左右留白；基线是完整横幅灰色棚景。不能把当前两档直接替换为日常基线。

在本次侧步案例中，0.8 的红色衣服区域横向质心变化较基线增加约 26%，0.7 增加约 8%；两档主体区域的光流变化也较基线多。质心同时受服装摆动、姿势和合成瑕疵影响，光流同时反映身体、衣服和合成变化，因此这些数值只是描述性运动代理指标，不等同于动作正确率、循环频率或质量提升。抽帧未发现明确身份交换或明显服装丢失；完整播放的细节质量、循环正确性和节奏仍待用户目视确认。

## 音频

音频流存在且时长匹配。均值电平：基线 -33.5 dB，0.7 为 -36.4 dB，0.8 为 -32.0 dB。0.8 解码浮点峰值约 1.051，约 0.0024% 样本绝对值达到 0.999，需要听音确认是否存在爆音；不能仅凭电平判断音画同步或声音自然度。本轮尚未听音验收。

## 当前建议与证据

可加载、可生成已验证。当前仅证明特定侧步案例的运动代理指标增加，同时有明显白边副作用；不支持普遍画质优势或默认生产替换。用户可用 comparison.mp4（静音）比较三档动作，再用各原视频试听声音。无需扩大跑批来得出这一阶段结果。

## 2026-10-03 画幅问题补测与归因修正

Owner: Sean。输出容器始终是 768×448；原 0.7/0.8 内有效区域的中位尺寸约 442×448，确实近似 1:1。竖幅参考原图 1344×1536，经原生 ref_image_size=match 缩为 544×640；节点按面积保比例缩放，没有自动加白边代码。

三个补测均保持权重 0.7、原 seed、20-step res_multistep/simple 与 768×448 输出；每条相对原 0.7 仅改变下列一个输入。

| 补测 | 改动 | 有效区域中位尺寸 | 白边是否消失 |
|---|---|---|---|
| no_ref_latent | 仅去掉 ReferenceToVideo 的 video VAE 输入，保留 Qwen 图像条件及原 prompt | 448×448 | 否，左右各约160px |
| fullwidth_prompt | 保持原参考图与 VAE，prompt 仅增加明确横幅/棚景铺满全画面语句 | 448×448 | 否，左右各约160px |
| landscape_ref | 保持原 prompt 与 VAE，仅将参考图换为 baseline 视频首帧的完整768×448横幅 | 768×448 | 是，124帧均未检出白边 |

因此不能将初测白边当作该 LoRA 固有的1:1输出限制，也不是输出宽高填错。结果支持参考图构图/图像条件与 LoRA 的交互影响画幅；使用接近目标输出比例的完整场景参考，是本例已验证的修正。横幅参考来自 baseline 视频解码首帧，无裁切；它同时改变了参考图布局与渲染外观，故不能声称已严格证明“只有比例”是唯一原因。关闭 VAE 或只改 prompt 均不是本例的解决办法。

新 case 的动作强弱不能与旧参考图的 baseline 直接当作单变量 LoRA 效果比较；若要比较运动提升，需让无 LoRA 与 LoRA 都使用这张新的横幅参考。本轮仅解决画幅诊断，没有继续扩展运动矩阵。

补测耗时依次67.476、70.375、69.487秒，均成功且无未加载键警告。新视频、history、ffprobe 和日志已归档，GPU lease 已释放。aspect_check.py 是全帧白边测量和诊断抽帧的复现脚本；aspect_diagnosis.json 保存阈值与各case数据。

## 采样速度与动作职责

回查原三档服务器日志的最后20/20进度：无LoRA与0.7均3.03秒/步，0.8为3.04秒/步，采样 elapsed 都显示01:00。该秒级日志下没有明显采样速度变化；不是重复随机化性能benchmark，不能建立所有场景零开销的结论。总耗时94.3/67.3/66.9秒混有首次加载、条件缓存、解码等非采样差异，不能解释为LoRA提速。数据见sampling_timing.json与baseline_runtime.log。

作者V2说明宣称更广动作覆盖、接触与回弹、次级身体跟随以及动作相关音频，不是减少采样步数的蒸馏加速模型。衣摆、头发、飘带可作为身体运动后的跟随表现；当前只测试了人物侧步，未验证独立风驱动飘带、布料物理或其他运动泛化。
