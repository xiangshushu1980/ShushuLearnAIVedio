依赖任务 T47-1（双角色 Continuum/参考图/接缝）与 T47-2（Continuum 一采→二采 + NativeAudioLock 嘴型）在核查时仍为 `active / in progress`，尚未提供可验收的最终源视频、音频锁定结果、双角色身份确认和分段清单。因此本轮没有启动 ComfyUI/FaceRefine，也没有把既有单脸或非同源输出当作双角色 Continuum 结论。

## 可复用的已知基线（不是本轮结论）

- FaceRefine 现行链路：单角色独立轨迹 → 768×768 crop、crop factor 3 → 原视频 crop latent + H3InjectVideoLatent → H3PerFrameDenoise → 8-step `res_multistep` → `face_only` stitch；双角色必须分别处理后再合成。
- 已有 8 秒单脸记录：约 222.3–275.1 秒/192 帧，采样显存约 23.1 GiB，系统可用内存最低约 375 MiB；因此不能直接把整段 32 秒送入 FaceRefine。
- 既有 209 帧（8 秒核心 + 17 帧上下文）对照记录：单段约 205.4 秒，峰值显存约 23.0 GiB，最低系统可用内存约 7.0 GiB；另一段约 201.2 秒，最低可用内存约 6.7 GiB。该记录可作为运行预算参考，不替代依赖输入验收。
- 17 帧的正确边界语义是“相邻输入保留 17 帧上下文”，不是跳过源视频帧：前一段保留核心帧 0–191，后一段输入应从前一段核心末端向前回退 17 帧，再丢弃后一段对应的重叠输出。旧的直接硬切方案曾测得切点 Y 差约 12.5/255；正确对齐的切点约 2.57/255。最终仍需在同一批 FaceRefine 双角色产物上复核。

## 依赖解除后的执行矩阵

1. 固定依赖任务交付的同一 Continuum 母片、NativeAudioLock 外部音频、双角色 reference、seed/模型/分辨率和每段帧边界；外部对白以音频为真值，不在 FaceRefine prompt 中重写台词。
2. 先为角色 A、角色 B 各生成/复用独立 manifest 或 ROI/identity gate，并输出 tracking preview；禁止用 `face-index=1` 作为双人身份锁定。
3. 每个 8 秒核心段实际处理 209 帧（核心 192 + 前后约定的 17 帧重叠，具体落点以 Continuum 帧表为准），参数固定为 768 crop、8 steps；两角色串行运行。
4. 逐角色按正确重叠规则裁出核心结果，再合成双角色结果；保留原始音频，不重新编码或重生成音轨。
5. 验收三类证据：嘴型/音频锁定保持、脸部 refine 质量、段间接缝。每类至少检查首/中/尾及每个边界附近帧，并保留 tracking preview、每帧目标框、运行日志和资源峰值。
