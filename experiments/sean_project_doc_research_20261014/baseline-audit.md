# 现有 project-doc-system 审计

Owner: Sean
日期：2026-10-14
对象：用户级规范源 `/home/sean/.pi/agent/skills/project-doc-system`，v1.0。
证据：现有 SKILL、index-skeleton、gitignore-template、case-study；本报告是文本审查，未进行模型行为测试。

| 观察 | 影响 | 改造方向 |
|---|---|---|
| 四层没有当前有效技术基线与决策记录位置，模板却链接“结论层” | 使用者无法区分当前值、历史证据、决定理由 | 按事实类别指定真源，补当前基线与决策记录 |
| 摘要被要求可整读，同时又禁止整读；追加流水承担当前状态 | 阅读入口与历史档案混淆 | 有界导航首页与追加研究索引分开 |
| 当前状态只在摘要维护，同时允许活跃 README 完整状态块 | 产生两处手工维护真源 | 明确任务系统、技术基线、历史记录各自权威 |
| 模板要求先更新状态，再写细节；正文要求先确认细节已有结论 | 可能发布没有证据的状态 | 先落证据，再发布基线/决定，最后更新导航 |
| `源码确认 < 静态推断` 与“四档”含五种名称 | 推断看起来比直接源码观察更可信 | 证据方式与结论状态独立，不把不同适用范围排成可信度总序 |
| 禁止在文档写日期、任务ID、实测数字 | 与基线参数、ADR、索引模板自身冲突 | 按用途和可追溯性判断，避免字面禁令 |
| 固定 git log/find/ls 第一调用；最近提交等于当前情况 | 未提交内容和历史热点可误导现状定位 | 从项目入口与真源定位，再按需用 git 发现变化 |
| 图片永不入库、vendor/.pi 整目录排除、ground-truth 文件名自动放行 | 忽略源码资产和项目技能；文件名不能证明证据或隐私可发布 | 按路径、体积、许可证与用途明确边界，模板仅作可选起点 |
| 没有替代/退役关系、断链迁移和治理步骤 | 旧结论仍可能被当当前使用 | 加范围审计、内容迁移、替代指针与按需校验 |

保留：单一权威正文、证据下沉、导航优先、增量档案条目级检索、git 可追溯、AGENTS 精简。

外部调研用于寻找可落地机制；这些审计观察本身不能证明某开源方案优于其他方案。
